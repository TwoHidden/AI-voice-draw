# AI 语音绘图工具 — 设计规格文档

## 一、项目概述

### 1.1 目标
开发一款纯语音控制的绘图工具，用户仅通过语音指令完成绘图创作。

### 1.2 核心创新点
**语音指令优化器** — 解决语音输入的口语化问题，提升指令理解准确率。

#### 为什么需要优化器？

直接将语音识别结果丢给 LLM 解析，存在以下问题：
- **识别噪声干扰**：口头禅、语气词会误导 LLM 理解，导致错误操作
- **上下文丢失**：语音断断续续，LLM 难以理解不完整的语句
- **响应延迟**：LLM 处理冗余文本耗时更长

采用"规则预处理 + LLM 语义优化"两层架构的优势：
- **速度**：规则层处理常见口头禅，毫秒级完成，减少 LLM 输入长度
- **准确率**：LLM 只处理清洗后的文本，专注于语义理解而非噪声过滤
- **可调试**：规则层可独立测试和调整，不依赖 LLM 响应
- **成本**：减少 token 消耗，降低 API 调用成本

### 1.3 技术栈
- 前端：React 18 + TypeScript + SVG + Vite
- 后端：Python 3.10+ + FastAPI + FunASR + mimo-v2.5-pro
- 通信：WebSocket (fastapi-websocket)
- LLM 接口：OpenAI 兼容 API（通过 httpx 调用）

### 1.4 仓库与开发周期
- **仓库平台**: GitHub（公开仓库）
- **开发周期**: 36 小时，从开题日起持续交付
- **提交方式**: 12 个 PR，均匀分布在开发周期内

## 三、语音指令优化器（核心创新）

### 3.1 问题分析

语音输入存在以下问题：
- **口头禅**: "就是"、"那个"、"嗯"、"然后"
- **语气词**: "啊"、"呢"、"吧"
- **语句不完整**: "画一个...矩形"
- **指代模糊**: "把它弄大一点"
- **语序混乱**: "红色的，画一个矩形"

### 3.2 优化流程

```
输入: "就是画一个那个红色的矩形，然后...嗯...再画个圆"
                ↓
┌─────────────────────────────────────────────────────┐
│ Layer 1: 规则预处理                                  │
│  - 去除口头禅: "就是"、"那个"、"嗯"、"然后"          │
│  - 去除语气词: "啊"、"呢"、"吧"                      │
│  - 标点规范化: "..." → ""                            │
└─────────────────────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────────────────┐
│ Layer 2: LLM 语义优化                                │
│  - 补全不完整语句: "画个圆" → "画一个圆形"            │
│  - 消除指代词: "把它变大" + 上下文 → "把矩形放大"     │
│  - 语序修正: "红色的，画一个矩形" → "画一个红色矩形"  │
│  - 拆分复合句: "画矩形和圆" → "画矩形；画圆形"       │
└─────────────────────────────────────────────────────┘
                ↓
输出: "画一个红色矩形；画一个圆形"
```

### 3.3 LLM Prompt（优化器）

```
你是一个语音指令优化助手。用户的语音输入可能包含口头禅、语病、指代不清等问题。

当前画布状态：
{canvas_state}

最近操作历史：
{operation_history}

请将以下语音输入优化为清晰的绘图指令：
- 去除口头禅和语气词
- 补全不完整的语句
- 解决指代词（"它"、"那个"等）基于上下文
- 拆分复合句为独立指令
- 保持原意不变

输出格式：每条指令一行，用分号分隔

语音输入：{raw_text}
```

### 3.4 前端展示

```
┌─────────────────────────────────────────────────────┐
│ 🎤 语音输入                                          │
│ ┌─────────────────────────────────────────────────┐ │
│ │ "就是画一个那个红色的矩形"                        │ │  ← 原始识别
│ └─────────────────────────────────────────────────┘ │
```

## 四、指令解析器

### 4.1 LLM Prompt（解析器）

```
你是一个绘图指令解析助手。将自然语言指令解析为 JSON 操作。

支持的图形类型：
- rect: 矩形
- circle: 圆形
- ellipse: 椭圆
- triangle: 三角形
- diamond: 菱形
- line: 直线
- arrow: 箭头

支持的操作：
- create: 创建图形
- delete: 删除图形
- move: 移动图形
- resize: 缩放图形
- setColor: 修改颜色
- setText: 添加文字
- undo: 撤销
- redo: 重做

当前画布状态：
{canvas_state}

输出严格的 JSON 格式，不要包含其他文字。

指令：{command}
```

### 4.2 输出 JSON Schema

```typescript
interface Command {

  target?: string;  // 图形 ID 或 'last' | 'selected' | 'all'
  props?: {
    x?: number;
    y?: number;
    width?: number;
    height?: number;
    radius?: number;
    fill?: string;
    stroke?: string;
    strokeWidth?: number;
    text?: string;
    fontSize?: number;
    dx?: number;
    dy?: number;
  };
}
```

## 五、指令执行器

### 5.1 数据模型

```typescript
interface Shape {
  id: string;
  type: string;
  x: number;
  y: number;
  width?: number;
  height?: number;
  radius?: number;
  fill: string;
  stroke: string;
  strokeWidth: number;
  text?: string;
  fontSize?: number;
  rotation: number;
}

interface Operation {
  id: string;
  type: string;
  targetId: string;
  prevState: Partial<Shape>;
  nextState: Partial<Shape>;
  timestamp: number;
}

interface CanvasState {
  shapes: Map<string, Shape>;
  undoStack: Operation[];
  redoStack: Operation[];
}
```

### 5.2 执行流程

1. **验证器** — 检查参数合法性、目标存在性、边界检查
2. **状态管理器** — 维护图形列表和操作历史栈
3. **操作执行器** — 执行具体操作，记录快照用于撤销/重做

### 5.3 撤销/重做机制

- 每次操作保存 `prevState` 和 `nextState`
- `undo`: 从 undoStack 弹出，恢复 prevState，压入 redoStack
- `redo`: 从 redoStack 弹出，恢复 nextState，压入 undoStack

## 七、后端 API

### 7.1 WebSocket 消息协议

```typescript
// 客户端 → 服务端
interface ClientMessage {
  type: 'audio' | 'command' | 'optimize';
  data: ArrayBuffer | string;
}

// 服务端 → 客户端
interface ServerMessage {
  type: 'asr_partial' | 'asr_final' | 'optimized' | 'result' | 'error';
  data: string | object;
}
```

### 7.2 消息流程

```
客户端                          服务端
  │                               │
  │ ── audio (PCM) ─────────────→ │ FunASR 流式识别
  │ ←── asr_partial ("画一个...") ─│
  │ ←── asr_final ("画一个红色矩形")│
  │                               │
  │ ── optimize ("就是画一个那个...")│ → LLM1 优化
  │ ←── optimized ("画一个红色矩形")│
  │                               │
  │ ── command ("画一个红色矩形") ──│ → LLM2 解析 + 执行
  │ ←── result (执行结果+画布状态) ─│
```

### 7.3 REST API（备用）

当 WebSocket 不可用时（如网络不稳定），REST API 作为降级方案。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/shapes` | GET | 获取所有图形 |
| `/api/shapes` | POST | 创建图形 |
| `/api/shapes/:id` | PUT | 更新图形 |
| `/api/shapes/:id` | DELETE | 删除图形 |
| `/api/undo` | POST | 撤销 |
| `/api/redo` | POST | 重做 |
| `/api/export/:format` | GET | 导出 PNG/SVG |

## 八、错误处理方案

### 8.1 语音识别异常

| 场景 | 处理方式 |
|---|---|
| 无声音输入 | 前端提示"未检测到语音"，不发送请求 |
| 识别结果为空 | 提示"未能识别，请重新说话" |
| 识别置信度低 | 提示"识别不确定，请确认"，显示识别结果供用户确认 |
| FunASR 服务不可用 | 前端显示"语音服务不可用"，降级为文字输入模式 |

### 8.2 LLM 服务异常

| 场景 | 处理方式 |
|---|---|
| API 超时 (>10s) | 提示"服务响应超时"，允许重试 |
| API 返回错误 | 提示"服务异常"，显示错误码 |
| 返回非 JSON | 提示"指令解析失败"，显示原始文本供用户修改 |
| API Key 无效 | 提示"API 配置错误"，引导检查配置 |

### 8.3 指令执行异常

| 场景 | 处理方式 |
|---|---|
| 目标图形不存在 | 提示"未找到目标图形" |
| 参数越界 | 自动修正到合法范围，提示用户 |
| 不支持的操作 | 提示"暂不支持该操作" |
| 指令模糊 | 提示"请更具体地描述"，列出可能的选项 |

### 8.4 网络异常

| 场景 | 处理方式 |
|---|---|
| WebSocket 断开 | 自动重连（最多 3 次），失败后提示并降级为 REST API |
| 网络延迟高 | 显示加载状态，设置超时提示 |

## 十、开发计划（36 小时）

- 前端：React 18 + TypeScript + Vite

- Node.js >= 18

# 后端
cd backend
pip install -r requirements.txt

export LLM_API_KEY="your-api-key"

python main.py

npm run dev
