# 语音指令优化器设计文档

## 概述

改进现有的语音指令优化器（optimizer.py），从"规则预处理作为 LLM 兜底"升级为"规则引擎为主 + LLM 兜底"的三层管道架构。核心目标：将 ASR 识别的口语化文本转换为标准绘图指令，并在前端展示优化过程。

## 当前状态

现有 `optimizer.py` 有两层架构：
- **规则预处理**（`rule_preprocess`）：去语气词、动词标准化、形状/颜色映射
- **LLM 优化**（`llm_optimize`）：调用 LLM 清理口语表达

**问题：**
1. 规则预处理的结果没有传给 LLM — LLM 收到的是原始 ASR 文本
2. 规则引擎只作为 LLM 不可用时的兜底，没有置信度判断
3. 缺少指代消解、模糊表达解析等口语场景支持
4. 用户看不到优化过程

## 设计方案

### 整体架构

```
ASR 原始文本
    │
    ▼
┌─────────────────────┐
│  Layer 1: 规则引擎    │  ← 零延迟，覆盖 80% 场景
│  - 去语气词/口误      │
│  - 动词标准化         │
│  - 形状/颜色映射      │
│  - 模糊表达解析       │
│  - 指代消解           │
└─────────┬───────────┘
          │
          ▼
    规则处理结果 + 置信度分数
          │
          ├── 置信度 >= 0.7 ──→ 直接进入解析器
          │
          └── 置信度 < 0.7  ──→ 进入 Layer 2: LLM 优化
                                   │
                         LLM 收到: 规则预处理结果 + 原始文本
                         LLM 输出: 标准指令文本
                                   │
                                   ▼
                              进入解析器
```

### Layer 1: 规则引擎

规则引擎是一个管道（pipeline），每个阶段按顺序执行：

#### 1.1 去噪层

移除语气词和填充词：

```python

    "这个", "那个", "呢", "吧", "呀", "嘛"

```

输入: `"嗯那个帮我画一个红色的长方形就是那种大一点的"`
输出: `"帮我画一个红色的长方形大一点的"`

#### 1.6 指代消解层

解析代词引用，指向已有图形：

```python
REFERENCE_PATTERNS = [
    (r"刚才那个|最后那个|最后画的|刚才画的", "last_created"),

    (r"第三个", "index:2"),
```

#### 1.7 置信度评分

```python
def calculate_confidence(original: str, processed: str, matched_rules: list) -> float:
    score = 0.0
    if matched_rules:      score += 0.3  # 匹配到了规则
    if shape_found:        score += 0.3  # 识别到了形状
    if operation_found:    score += 0.2  # 识别到了操作
    if color_found:        score += 0.1  # 识别到了颜色
    if no_unknown_chars:   score += 0.1  # 没有未识别字符
    return min(score, 1.0)
```

阈值：`>= 0.7` 直接进解析器，`< 0.7` 进 LLM 优化。

### Layer 2: LLM 语义优化

当规则引擎置信度不足时，调用 LLM 进行语义优化。

**输入格式：**
```
system: 你是一个语音绘图指令优化器。将口语化的语音输入转换为简洁的标准绘图指令。
        规则：1. 去除语气词、重复、口误 2. 保留核心意图和参数 3. 输出简洁的指令文本
        支持的操作：创建、删除、移动、resize、setColor、setText、undo、redo
        支持的形状：rect、circle、ellipse、triangle、diamond、line、arrow

user: [规则预处理结果]
      {rule_processed_text}

      [原始语音]
      {original_text}
```

**关键改进：** LLM 收到两个版本 — 规则预处理结果 + 原始语音。LLM 可以参考规则结果，同时利用原始语义做判断。

**输出：** 优化后的标准指令文本（纯文本），传给解析器。

**错误处理：**
- LLM 超时（>10s）→ 回退到规则预处理结果
- LLM 返回格式异常 → 尝试提取文本，失败则用规则结果
- LLM API 未配置 → 直接使用规则引擎

### 后端数据模型（models.py 新增）

```python
class OptimizeResult(BaseModel):
    original: str           # ASR 原始文本
    rule_processed: str     # 规则预处理结果
    final: str              # 最终优化结果
    used_llm: bool          # 是否调用了 LLM
    confidence: float       # 规则引擎置信度 (0.0 ~ 1.0)
```

## 测试策略

### 单元测试（规则引擎）
- 每个规则层独立测试
- 边界情况：空字符串、纯语气词、无法识别的输入
- 置信度评分验证

### 集成测试（优化管道）
- 完整管道：ASR 文本 → 规则 → (可选 LLM) → 最终结果
- LLM 失败回退测试
- 高置信度跳过 LLM 测试
